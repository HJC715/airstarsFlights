## 2. 功能範圍與七步驟流程

### 2.1 行程與旅客

- **【已確認】** 單程（one-way）、來回（round-trip）、多城市（multi-city）；多城市預設 2 個航程，使用者可新增／刪除至 2–4 個，每個航程可自行調整起點、終點、日期，新增時預填前一航程的終點但可覆寫。
- **【已確認】** 每筆訂單限成人（1–9 位），不提供兒童、嬰兒、膝上嬰或兒童折扣；每人均佔一個座位。
- **【已確認】** 可搜尋出發日落在未來 365 天範圍內的航班。**【實作預設】** 日期可選今日起共 365 個當地曆日（today 到 today+364，含端點）；每段起飛時間必須晚於即時 UTC 現在，預設至少提前 2 小時可訂（避免搜尋已起飛航班）。
- **【已確認】** 只提供直飛或最多一次轉機；不憑空造出兩座機場間不存在的直飛航班。

### 2.2 七步驟與成功頁

1. **航班與票種**：先選每個旅行方向／多城市航程的有效直飛或一轉航班；各實際飛行段可混合艙等；每個單方向聯程只選一個票種（超值、基本、彈性）；顯示航班、機型、時區、轉機、票價與條款。
2. **旅客資料**：依成人數建立英文名／姓、稱謂、出生年月日、國籍、必要旅遊證件資訊及一組訂單聯絡人資訊；可一鍵填入**虛構測試資料**。
3. **行李**：對每位旅客及每單方向聯程顯示免費件數與 kg，允許加購最多三件，逐次即時計價。
4. **選位**：按每位旅客／每實際飛行段／實際執飛機型開啟互動座位圖，處理客艙及艙等限制、不可選座、座位費與防重複。
5. **餐點**：按每人每實際飛行段選一般餐、艙等餐或特殊餐；不增加費用。
6. **訂單確認**：列出航班、旅客、艙等、票種、座位、餐點、行李、退改條款與所有費用；重要項目可返回先前完成步驟修改。
7. **模擬付款**：只選預設虛構測試卡片，不輸入真實卡號；播放處理動畫、模擬成功／失敗。

**付款成功後**進入**獨立確認畫面**，顯示六碼 PNR、每位旅客的虛構電子票號、所有航段及可下載的 A4 PDF。確認頁不計入七個訂票步驟。

### 2.3 返回修改與資料相依性

**【已確認】** 已完成步驟可返回編輯，僅失效並清除受修改影響的航班、座位、餐點、權益與加購資料，保留不受影響的旅客資料與其他航程；重新驗證日期、機型艙等、可售量、座位衝突、票種權益和總價。修改航班前如會清除選位等內容，先提示確認。必要前置資料未完成，不允許跳步。付款處理中鎖定表單與提交；付款失敗留在付款步驟且保留訂單；完成後不提供修改已完成訂位的功能。

### 4.4 班表生成、序列化與驗證

- 將上列**全部航班對**序列化為 `assets/data/schedules.js`（或 `schedules.json`）；每對展開成兩筆 `flightTemplate`，各包含：`flightNo`、`origin`、`destination`、`departureLocalHHmm`、`daysOfWeek`、`durationMinutes`、`aircraftType`、`routeKey`、`routeDemandFactor`、`direction`。
- 38 筆雙向航線主檔另可放 `routes.js`，指定 `origin`（TPE 或 KHH）、`destination`、`factor`、`greatCircleKm`、`marketRegion`。**同一組航線去回需求係數相同**。
- `flightTemplate` 不是實際發生日期的航班；搜尋日期 D 只有在 D 的起點當地 ISO weekday 位於 `daysOfWeek` 才展開為 `flightInstance`，其鍵為 `${flightNo}|${YYYY-MM-DD}`。
- 避免 DST 歧義：航班起飛時間都避開 02:00–04:00 的常見切換窗；遇歷史／未來時區規則變化，以 TZDB 為準。ISO local→UTC 要有可驗證的時區解算，不能直接 `new Date('YYYY-MM-DDTHH:mm')` 當作機場當地時間。
- 固定班表的實例、艙等容量、航線距離、班號唯一性、營運星期與機型合法性，都要在載入時通過校驗；回程使用不同起點時區，不要直接加或減固定小時數。
- **【實作預設】** 在搜尋結果中，對於本日尚未起飛、但不足 2 小時的航班視為不可訂；已過航班不顯示。可訂日期今日到+364天，共 365 個日期。異常日期或不存在的連接返回「無可售航班」，不改動班表。

## 5. 航班搜尋、轉機與排序

### 5.1 搜尋參數

單程：起訖機場、出發日期、成人 1–9、需求艙等；來回另選回程日期；多城市每航程一組起點／終點／日期。搜尋前要校驗：同起訖不允許、日期範圍合法、來回與多城市順序依真實 UTC 起降時序有效、旅客數在範圍內、至少一種可搭乘艙等。選取航班後展示三票種及逐段艙等（特別是混合艙等聯程）。

### 5.2 轉機條件【已確認】

- 最多 1 次轉機，限 TPE 或 KHH **同一機場**站內轉機，等候 **90 分鐘（含）至 18 小時（含）**。
- 不可跨機場（如 NRT→HND）、不新增 TPE⇄KHH 接駁、不得繞行起點作為中途站、不得形成重複機場迴圈。
- 各段航班均須真實存在於固定週班表的有效日期，且依 UTC 驗證轉機時間；允許跨日、跨時區與 DST。
- 混艙：同方向不同實際飛行段可以有不同艙等，必須依各型號可用艙等及當日可售量選擇；單方向所有實際航段**共用同一票種**。
- 聯程免費託運行李：件數取各段件數的最小值、每件重量上限取各段允許重量的最小值；額外行李以單人／單方向行程僅加一次費，有任何歐洲／北美／大洋洲段就採洲際費率；每人每方向最多加購三件。
- 聯程機票及模擬稅費按實際飛行段各自計價後加總，座位與餐點按旅客／實際段選擇。

### 5.3 搜尋排序與鄰近日期【已確認】

僅提供：**最低總價、最早起飛、最早抵達、最短總旅程**四種排序。預設最低價；總價包含選定艙等、票種的機票及基礎模擬稅費，未選的個人附加服務不得混入比較。總旅程為首次起飛 UTC 到最終抵達 UTC，含轉機等待。排序價相同時，按總旅程、出發 UTC、航班號作穩定 tie-break。

顯示搜尋日期前後**各 3 天**（七日期帶，超出365日範圍不提供），每個日期都以同樣乘客人數、既定艙等及票種資格，計算**該日期實際存在的最低可售票價**；無班次顯示「無航班」。點選日期即重跑對應日期搜尋。沒有進階過濾、複雜條件篩選、側邊並排航班比較功能。

### 5.4 售價可用性的搜尋級條件

每個 `flightInstance + cabin` 需有座位圖容量及可售數；當可售數 < 旅客人數，該艙等不可購買。含轉機行程每段皆須滿足同一組旅客人數；如某段沒有頭等艙，不得硬造頭等座位，可選另一艙等並標明混合艙等。已占座位不可選，同一訂單內座位不得重複指派。

### 8.6 固定模擬占位與可售庫存【已確認＋實作預設】

- **【已確認】** 依 `${航班號}|${出發當地YYYY-MM-DD}|${艙等}` 的固定種子得到座位占用；同條件跨搜尋一致；實際占位座位總數應與 §6 座位圖一致，剩餘數小於本訂單乘客數時不可選該艙。
- **【實作預設】** 使用穩定 `FNV-1a 32-bit` 字串雜湊。生成 `r = hash(seed) % 100`：`r=0` 設占用 100%（低機率售罄）；`r=1..4` 設占用 87%–96%（接近售罄）；其他 `r` 設占用 `20% + (hash(seed+'|occupancy') % 61)%`（即 20%–80%）。占用席數為 `min(totalSeats, floor(totalSeats*ratio))`，但 `r=0` 時強制 totalSeats。將該機型該艙所有 seat ID 按 `hash(seed+'|'+seatId)` 升序排序，取前 `occupiedCount` 個為固定占用座位；其餘可售。座位選中產生本筆記憶體訂單的暫時保留（不造成跨使用者伺服端扣量）。
- 模擬庫存僅是網站演示，不宣稱所有訪客共享即時庫存；重新整理後新分頁仍依固定種子得到相同原始庫存，但舊訂位不留存。

### 8.7 售價公式、整數化與總價

對每位旅客、每個實際飛行航段：

```text
routeBaseTWD = distanceBandBase[HaversineKm] * routeDemandFactor
rawFareTWD  = routeBaseTWD
            * cabinMultiplier
            * fareFamilyMultiplier
            * dateFactor
            * advanceBookingFactor
            * remainingInventoryFactor
fareTWD     = Math.round(rawFareTWD)   // 每人每段四捨五入為整數 TWD
segmentTaxTWD = distanceBandTax[HaversineKm]   // 不乘任何倍率

orderTotalTWD = Σ(每位旅客每段 fareTWD + segmentTaxTWD)
              + Σ(每位旅客每方向額外行李費)
              + Σ(每位旅客每段付費座位費)
```

當跨多個航段或旅客時，先依上式各段取整數 TWD，然後加總；**不要先以外幣運算**。季節／提前／庫存係數在同一 `flightInstance` 同一艙等中對所有旅客一致。訂單摘要和 PDF 必須以同一筆 `priceBreakdown` 資料為來源。
